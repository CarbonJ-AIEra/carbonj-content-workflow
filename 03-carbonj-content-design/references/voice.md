# CarbonJ 写作口径

## 默认风格

- 像真实使用者分享，不像产品新闻稿。
- 用具体场景开头：谁在什么情况下遇到什么麻烦。
- 先说读者能解决什么，再说工具或方法叫什么。
- 写出实际操作和能看见的结果，少写“赋能、重塑、全新体验、重新定义”等空泛表达。
- 标题兼顾钩子与搜索语义，不用无依据的夸张词制造点击。
- 句子短一些，允许自然口语，但不故意制造廉价情绪。

## 事实口径

- `verified`：字幕、口播稿或用户材料直接支持，可作为事实写。
- `attributed`：作者自报、受访者声称或第三方估算，正文必须保留“自报、据其介绍、按当前价格粗略计算”等归因。
- `uncertain`：不能确认，只能删除或明确写成待确认，不可润色成事实。
- “爆款、全网第一、保证、轻松赚钱、人人都能”等表述默认不用，除非用户提供可靠证据且内容准确保留限定条件。

## 内容结构

优先使用：

`真实场景或冲突 → 具体痛点 → 做了什么 → 可见结果 → 谁适合用 → 克制的行动引导`

不要强迫每个平台都使用完整结构。短平台保留最关键的冲突与结果；长平台补充过程、边界和证据。
