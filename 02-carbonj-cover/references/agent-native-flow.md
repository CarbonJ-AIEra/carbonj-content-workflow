# carbonj-cover · Agent 自主执行模式（SOP）

这是 carbonj-cover 的 Agent 自主执行轨道：不使用 `generate_carbonj_cover.py` 做选帧、分析或生图，不需要外部 Gemini 和 ZenMux key。执行 Agent 用自身多模态能力选帧、分析，并用参考图生图工具独立生成每个画幅的完整最终封面。

## 何时使用

- 用户明确要求自主模式、不要脚本，或要求 Codex 直接执行。
- 当前环境缺少脚本依赖或 ZenMux key，但具备多模态视觉与图生图能力。

否则使用脚本模式。

## 前提与规则来源

执行 Agent 必须具备多模态视觉和支持参考图的生图工具。在 Codex 中使用 `.system/imagegen` 的 `image_gen` 工具；先用 `view_image` 将选中的真实屏幕帧和产品 Logo 加载进上下文，再在 prompt 中引用。

开跑前必须完整阅读 `references/cover-rules.md`。本 SOP 只描述执行过程，视觉判断以该文件为准。

## 产物目录

- 在视频或截图同目录创建 `<文件名>.carbonj-cover/`。
- 其中保留 `frames/`、`analysis.md`、`cover_plan.md`、六份 `.prompt.md`、六张 `<画幅>.generated-base.png` 与生成记录。
- 最终图写回输入同目录：`<文件名>_3x4.png`、`_4x3.png`、`_16x9.png`、`_2.35x1.png`、`_youtube_16x9.png`、`_youtube_9x16.png`。

## 复用现有结果和恢复

每个画幅开始前，先检查正式输出路径及用户提供的生成图片路径。正式文件已经存在、可打开且比例正确时，直接登记并跳过生图。若用户给了 `generated_images/...png`，把它作为已完成结果检查；画幅匹配就无损复制到正式文件和 `.generated-base.png`，再更新 `generation-record.json`。如果比例不符，可保留为当前任务的风格参考，但不要把它算作已完成画幅。不要把某一次提供的风格参考路径写成长期默认资产。

调用图像工具并收到一个画幅的图片路径后，马上将该图复制到最终文件和 `.generated-base.png`，写下尺寸、来源路径和完成状态，并向用户给出该画幅已完成的进度。逐张调用是默认方式。若使用并发，每个请求的完成处理必须独立触发保存、登记和进度反馈，不能等全组 `Promise.all` 结束才取回路径。全部画幅完成验收后再写最终版 `manifest.final.json`。出现中断时，下次只补缺失或验收失败的画幅。

## 执行步骤

### 0. 确认标题

标题确认前，不得取帧、调用图像工具或写最终图片。用户未提供标题时，根据字幕/文稿和视频主题给出 5 个有钩子的候选；用户已给标题时只询问是否确认。确认后，标题不得在后续流程被擅自改写。

### 1. 建工作目录与选帧

- 视频先抽取 4–8 张候选帧，逐张按 `cover-rules.md` 选择真实、清晰、最能说明主题的一帧，再抽取该时刻全分辨率版本。
- 同时从当前视频中选择清晰自然的本人画中画，从视频帧截取头像区域保存为 `frames/avatar-reference.png`，记录视频时间点并通过 `view_image` 查看。头像参考与内容证据分开；每次任务均取自当前视频，不复用历史头像。若找不到清晰可辨的本人头像，说明情况，请用户提供参考或明确选择本次无头像。
- 截图或关键帧输入直接使用。
- 在 `analysis.md` 记录选中的画面和原因。没有合适实操画面时说明缺口并请用户决定，不要硬凑。

### 2. 分析内容与匹配 Logo

在 `analysis.md` 明确主主题、主产品、承载界面、一眼主语、主/辅助证据和可牺牲信息。读取 `product-assets.md` 和 `assets/product-logos/`；存在可信 Logo 时作为参考图，否则以真实截图中的产品识别为准。

### 3. 写方案与独立提示词

- 在 `cover_plan.md` 写六个画幅的标题断行、构图、证据和 Logo 位置。
- 先建立一份共享风格锁：固定标题字体气质和字色、底色与 1–3 个具体邻近氛围色、网格/纸感、卡片边线和圆角、阴影、关键词强调方式、Logo 大小与位置关系。保存于 `cover_plan.md`，并逐字复用到每份提示词中；画幅差异只用于适配布局和标题断行。
- 若用户提供风格封面，把它标为“风格参考图”，只提取上述视觉特征；视频帧仍标为“内容证据图”。在提示词中明确两者职责，防止风格图内容覆盖当前主题。
- 若没有用户风格参考，先生成并保存一张主版；其余画幅使用这张主版作为风格参考。主版的完整构图不能被复制，其他画幅必须针对自己的比例重新组织标题与真实证据。
- 分别写 `3x4`、`4x3`、`16x9`、`2.35x1`、YouTube `16x9` 和 YouTube Shorts `9x16` 的完整 prompt sidecar。
- 每一版必须是独立构图：明确精确比例、真实证据提炼方案、标题层级、背景、主证据与删除项；保持共享风格锁一致，不得裁切或复制另一画幅充数。
- 每份提示词明确把从本次视频截取的本人头像参考放在画布右下角安全区，大小适配画幅，避开标题和关键证据；生图时同时传入该头像参考，并要求保持人物辨识度。不得添加其他人物或角色；不得本地贴头像。
- 写完 sidecar 才可调用生图工具。

### 4. 生成并写入最终图

- 真实屏幕帧和 Logo 仅作参考，不做整张复刻。
- 每个缺失画幅单独生成一次。只有能在每个请求完成时立即取回并保存该请求结果，才并发生成；不要用一个全批次等待隐藏已完成的图片路径或进度。
- 对每个已返回结果，立即复制为正式文件和 `.generated-base.png`，追加当前最终状态到生成记录，并报告已完成画幅。已有且有效的结果跳过，不重复生成。结束条件是所有目标画幅已有有效文件且全部完成登记。
- 生成的图片直接保存为最终文件和 `.generated-base.png`；禁止任何本地合成、贴图、裁切、重排或视觉修补。

### 5. 质检与收尾

逐张检查：标题可读、产品识别可信、主证据够大、无完整截图噪音、无固定顶栏，平台比例正确，且与共享风格锁一致；核对头像来自本次视频、位于右下角、不遮挡标题和证据且人物可辨。失败时只重跑失败的单一画幅；沿用原风格参考图和风格锁，不动通过验收的文件。

确认输入同目录存在全部目标图片，工作目录存在分析、方案、六份 prompt、生成记录和生成底图。

## 不可违反

- 不要在生图后本地贴字、贴 Logo、拼接、裁切、重排或视觉修补。
- 仅允许使用从本次视频截取的本人头像作为人物参考，放在右下角；不添加其他人物或角色。
- 默认不加固定顶部 Panel、品牌字标、顶栏或横线，除非用户单次明确要求。
- 只使用当前视频、标题、字幕、截图、Logo 和用户补充信息，绝不带入历史任务内容。
- 每次生图前保存 prompt，完成后保留 `analysis.md`、`cover_plan.md`、prompt、生成记录与最终图；文档只描述当前最终状态。
